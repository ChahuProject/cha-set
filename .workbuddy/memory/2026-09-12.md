## CodeBlock 组件化设计（调研 + 方案，尚未落码）

**背景**：Showcase 里的 `CodeBlock.tsx` / `CodeBlock.qml` 是双端 1:1 的 showcase 内部组件，
由 CopyButton + ScrollArea 自举拼装，**无语法高亮**。
目标：提升为 ChaSet 正式组件，组合式设计，支持语法高亮。

**方案要点**

- 分层：L0 既有原语 → L1 spec 共享词法层（`spec/highlight/languages.json` + `tokenizer.mjs`，单一真理源）
  → L2 高亮渲染原语 → L3 结构件（Header / Content / LineNumbers）→ L4 复合 `<CodeBlock>`。
- 高亮引擎：**自研 spec 驱动词法器**（声明式规则表 + 单遍 sticky 正则扫描，输出 `{t,v}[]`），
  由 `generate-highlight.mjs` 产出 React `.ts` 与 Qt 可 import 的 `.js`。
  拒绝 Prism/Shiki：Shiki 依赖 WASM/Oniguruma 且**无法在 QML 运行**；Prism 需另写 Qt 端口 → 破坏双端一致性。
- Qt 渲染：`Text { textFormat: RichText, wrapMode: NoWrap }` + HTML span
  （空格→`&nbsp;`，换行→`<br/>`，先做 HTML 转义）。
  保留 `implicitWidth/implicitHeight`，故 `ChaSetScrollArea.contentWidth/contentHeight` 绑定不变。
- 新增 12 个语义 token：`code-keyword|string|number|comment|function|type|operator|punctuation|property|tag|attribute|variable`，
  加进 `spec/tokens/semantic/core.json`（纯加法式）。
  **syntax 配色设计为 preset-independent**（launcher / dunting 取同值），
  规避「showcase 基色来自自身 styles.css、Qt 用 dunting」的分歧。

**勘察到的硬约束 / 坑（重要）**

1. `spec/validate-tokens.mjs` 硬断言 `qt.colors === 33` 且 `qt.rgbf === 33`；`generate-qt.mjs` 的
   `COLOR_ORDER` 与之对齐。→ **绝不能**把 code token 塞进 `qt-mapping.json.colors`，
   否则校验失败，且会破坏下游 dt-a 的 `ThemeManager::Tokens` C++ 契约。
   必须走独立产物 `qt/src/CodeTokens.generated.qml`。
2. `spec/load-tokens.mjs` 的 `SHARD_REL_PATHS` 是**硬编码**列表 → 新增 shard 文件需同时改 loader 与
   build-tokens；改走现有 `semantic/core.json` 可零改动。
3. `gate/parity.mjs` 对 `spec/components/*.ts` 默认推断 `${Pascal}DocPage.tsx` /
   `ChaSet${Pascal}.qml` / `${Pascal}DocPage.qml` + `Main.qml` 路由 + CMake 注册
   → `code-block` 走默认推断即可，**无需**加 specialMap 特例。
4. `generate-css.mjs` 的 `semanticBlocks()` 泛型遍历 `spec.semantic` → 加 token 会自动产出 `--cs-code-*`，
   零改动。但 `packages/react/src/styles/theme.css` 是手写的，需补 12 行 `--color-code-*` 映射。
5. `.gitignore` 忽略 `dist/`，故 `dist/consumers/**/generated/*` 是构建产物；
   而 `qt/src/ThemeTokens.generated.qml`、`packages/react/src/styles/tokens.css` 是**被跟踪**的生成物
   （仓库既有惯例：消费者需要的生成文件写进 src/ 并提交）。

**迁移面（自举债务）**

- `qt/src/CodeBlock.qml` 被 **64 处**引用；`packages/react/examples/basic/src/components/CodeBlock.tsx`
  被约 50 个 DocPage + `ComponentPreview` 引用。
- `ComponentPlayground.tsx` 手写 `.code-snippet-box` / `.code-snippet-pre`（`styles.css` 亦有对应样式）
  → 属 Dogfooding 红线违规，应替换为 `<CodeBlock>`。
- 建议拆两个 commit：`feat(react,qt): add code-block component`
  + `refactor(showcase): migrate to ChaSetCodeBlock`。

**环境备注**

- **Bash 工具在本机不可用**（PortableGit coreutils 缺失，exit 127 `command not found`）。
  改用 **PowerShell 工具**（pwsh 7.6.5 Core / node v22.22.2 / pnpm 11.6.0 / git 2.55.0）。
- 但 PowerShell 工具的 stdout **不回传** → 统一采用「命令结果写临时文件 + Read 读回」的模式。

**状态**：方案待用户确认（高亮引擎选型 / API 广度 / 迁移范围），尚未落码。

## CodeBlock 组件化：已交付（双端 + 迁移 + 门禁全绿）

**结果**：CodeBlock 已提升为 ChaSet 双端正式组件，采用组合式设计（Card/ScrollArea/Tabs/CopyButton/Badge
原语 + spec 自研词法器）。本地旧实现已删除：`packages/react/examples/basic/src/components/CodeBlock.tsx`、
`qt/src/CodeBlock.qml`；共迁移 React 50 个文件、Qt 45 个文件。

**新增产物**
- React：`packages/react/src/code-block/{CodeBlock,CodeBlockHeader,HighlightedCode,index,tokenize.generated}`；
- Qt：`qt/src/{ChaSetCodeBlock,ChaSetHighlightedCode,Highlighter.generated,CodeTokens.generated}.qml`；
- 文档页：`CodeBlockDocPage.tsx` / `CodeBlockDocPage.qml`（含 App.tsx 路由、Main.qml `case "code-block"`、
  showcase-pages.test.tsx 冒烟清单、keyboard-shortcuts.json `code-block` 条目）。

**本轮踩到的坑（复用价值最高）**

1. **React showcase 测试解析到了陈旧的 `dist/` 预构建包**。`examples/basic/vite.config.ts` 把
   `@chahu/cha-set` alias 到 `src/index.ts`，但 `packages/react/vitest.config.ts` **没有** alias，
   于是 vitest 走 package.json 的 `module/exports` → `packages/react/dist/index.js`。
   后果：新增组件的导出在测试里是 `undefined`（React 报 "Element type is invalid ... got: undefined"），
   且 `pnpm gate` 内含 vitest 但不含 build，**全新 clone（无 dist）会直接解析失败**。
   修复：给 vitest.config.ts 加与 showcase 相同的 alias（已提交）。
2. **jsdom 的 `getAnimations` shim 会反噬 Base UI**。Base UI `useAnimationsFinished`
   按 `typeof el.getAnimations === 'function'` 分支：一旦 shim 存在，弹层会**等待退场动画**才卸载
   （异步），导致 AlertDialog/ContextMenu/DropdownMenu 的 Escape 关闭断言失败（4 例）。
   正确做法：保留 shim（ScrollArea viewport 会无条件调用 `getAnimations()`），**同时**
   设 `globalThis.BASE_UI_ANIMATIONS_DISABLED = true`（Base UI 官方逃生阀）。
   → 以后若再加该 shim，务必连这个 flag 一起加。
3. **QML 保留字**：生成器若产出 `readonly property color function/property/operator: ...`，
   `qmlcachegen` 报 `Expected token 'identifier'` 直接编译失败。CodeTokens 现在**只暴露
   `colorFor(type)`**，不再发射 per-type 属性。
4. **生成的 QML 单例必须登记到 `qt/CMakeLists.txt`**：既要进 `ChaSet` 模块的 QML_FILES，
   也要有 `set_source_files_properties(... QT_QML_SINGLETON_TYPE TRUE / QT_QML_SOURCE_TYPENAME X)`，
   否则 `import ChaSet` 看不到它们（Highlighter/CodeTokens 之前就漏登记）。
5. **Qt 运行时场景测试会遍历 `ShowcaseData.navigation`**（由 navigation.json 生成）→
   只加导航条目而不加 `Main.qml` 的 `getPageSource` 路由 + 可实例化的 DocPage，`pnpm gate` 必失败。
6. **Base UI 菜单 Group 语义**：`DropdownMenuLabel` / `ContextMenuLabel` / `SelectLabel` 必须在
   `Group`/`RadioGroup` 内，否则抛 `MenuGroupContext is missing`（DropdownMenuDocPage、Header 曾踩）。
7. `CodeTokens.dark` 现为 `readonly property bool dark: ThemeTokens.dark`（生成器补 `import ChaSet`），
   主题切换实时跟随，不再需要手工同步。

**环境（重要）**

- **本机 git 只在关闭沙箱时可用**：沙箱下 `.git` 内容被隐藏，git 报
  `fatal: not a git repository`；一次沙箱内 `git stash` 尝试后 `.git/objects/pack/*.pack` 丢失
  （仅剩孤儿 .idx），refs/index/config 完好。恢复方式：`git fetch origin` 重新拉回对象
  （已推送的提交全部找回，未提交改动都在工作区，无损）。**结论：git 读写一律用
  `dangerouslyDisableSandbox: true`。**
- 验证基线：React 100 文件 / 550 测试全绿 + `tsc --noEmit` 0；Qt 构建 OK，
  52 个 DocPage 全部实例化零错误；`pnpm gate` 4 项全过（330 capability / 49 components）。
- 提交（`main` 已推送）：`6690e46` TokenType 字面量联合 → `265e386` vitest 与浏览器语义对齐 →
  `eb1811e` 修复菜单 Group 与 Badge 导入 → `c99e1b7` spec 契约/能力/覆盖率 →

## 历史线性化：消除 merge commit 3f06554（已 force push）

**诉求**：`main` 上出现了合并提交 `3f06554 Merge branch 'feat-add-animations-KEkswM'`。
项目 `branch-sync` 技能与 commitlint 都禁止 merge commit（无 `merge` 类型），要求线性历史。

**做法（关键：全程零工作区改动）**

- 先证明合并是**干净的非 evil merge**：
  `git merge-tree --write-tree 182b467 f116fe0` == `git rev-parse 3f06554^{tree}`（同 `41552ccd`）
  → 说明没有任何手工冲突解决，线性化不会丢内容。
- 用纯 plumbing 重放，不 checkout、不 cherry-pick（避免触碰工作区）：
  对每个提交 C，`git merge-tree --write-tree --merge-base=C^ <当前tip> C^{tree}` 取新树，
  再 `git commit-tree` 重建（用 `GIT_AUTHOR_*` / `GIT_COMMITTER_*` 原样保留元数据）。
- 双重校验：12 个特性提交重放后的树 == 合并树 `41552ccd`；最终树 == 旧 tip 的树 `74f28c5e`。
- 应用：`git reset --soft <newtip>`（树相同，工作区/索引不动），再显式 lease 推送。

**结果**：`main` 2f652f2 → **d6ce7ff**，25 个线性提交，0 merge，内容与旧 tip 逐字节一致，已推送到 origin/main。
本地备份分支 `backup-pre-linearize-2f652f2`（= 旧 2f652f2）。

**新增防合并配置**：`pull.rebase=true`、`rebase.autoStash=true`、`merge.ff=only`。
（初版写在仓库 local，用户要求后已改为**全局** `C:/Users/Development/.gitconfig`，并清除仓库级重复项。）

**本轮新踩到的环境坑（重要，复用）**

1. **沙箱下 git 写入 `.git` 会被虚拟化**：`git branch backup/x`（需新建子目录）返回 0 但 ref 根本不存在；
   tag（平铺）却正常。**结论：git 读可以，涉及 ref 写入一律 `dangerouslyDisableSandbox: true`，
   且分支名尽量不用 `/`**。
2. **git 在本机写不进嵌套 ref 目录**：`refs/remotes/origin/*` 连 `git fetch` 都写不进去
   （fetch 报 `[new branch] main -> origin/main`，随即目录消失）。后果：
   隐式 `--force-with-lease` 必然报 `stale info`。
   → 两个应对：① 推送用 **显式 lease**
   `git push --force-with-lease=refs/heads/main:<远端sha> origin main`；
   ② remote-tracking ref 用 **Python 以二进制 `'wb'` + `\n`** 手写（用 `'w'` 会被写成 CRLF，
   `git fsck` 报 `trailingRefContent: has trailing garbage`）。
3. **被 SIGTERM 打断的 `git checkout` 会真的删掉工作区文件**（曾删掉 ~120 个 `packages/react/src/**`）。
   恢复：`rm -f .git/index.lock`（本机 `rm` 是坏的安全 shim，改用 Python `os.remove`）
   → `git checkout -f main`。**教训：大范围 checkout 优先用 plumbing 或临时 worktree 替代。**
4. `git fsck` 存在大量 `invalid reflog entry`（指向已丢失的旧对象，疑似之前「沙箱丢 pack」的旧伤）。
   `--no-reflogs` 检查全部干净，属历史遗留噪音，未处理；需要时可执行
   `git reflog expire --expire-unreachable=now --all`。

## Showcase dev 样式全丢失（Tailwind utilities 被 preflight 压过）—— 已修复并推送

**现象**：`pnpm showcase` 打开后界面「回退为默认 HTML 样式」—— 按钮无底色、无圆角、无边框，
Card 无边框，代码块无背景；但布局/间距/字号/文字颜色正常。

**根因：CSS Cascade Layers 顺序被污染**

- `packages/react/src/index.ts` 的 import 顺序是 `tokens.css` → `motion.css` → `theme.css`。
- `motion.css` 里有一个**裸 `@layer utilities { ... }` 块**，而 `theme.css` 才声明
  `@layer theme, base, components, utilities;`。
- CSS 规范：**一个 layer 的优先级位置由该 layer 名在文档中首次出现的位置决定，之后不再移动**。
  于是 `utilities` 被钉死在**最低**，实际顺序变成
  `utilities < properties < theme < base < components`（`components` 反而最高）。
- 后果：`@layer base` 的 Tailwind preflight
  （`button, input, select, ... { background-color: transparent; border-radius: 0 }`）
  **压过** `@layer utilities` 的 `.bg-primary` / `.rounded-lg` / `.border-*` 等。
- **为什么只在 dev 复现**：`vite build` 会把 CSS 合并成单文件且 theme.css 的 layer 语句排在最前，
  顺序天然正确 —— 所以 build/preview 一直正常，只有逐个 `<style>` 注入的 dev 模式会踩到。
- **自洽佐证**：① 动态新建的 `<div class="bg-primary rounded-lg">` 样式正常（base 里没有针对
  `div` 的规则），而页面上的 `<button>` 全部失效；② 往各 layer 注入同色探针，赢家是
  `components`/`utilities`，而非预期的 `utilities` 唯一最高。

**修复**：在 `motion.css` 的 `@layer utilities` 块**之前**声明完整规范顺序
`@layer properties, theme, base, components, utilities;`（与 theme.css 对齐，并补上 `properties`）。
把 `properties` 一并纳入声明很关键 —— 它承载 `* { --tw-*: initial }` 重置，若位置不定会浮到最高层，
把 `.shadow-*` / `.ring-*` 依赖的 `--tw-shadow`、`--tw-ring-*` 全部重置（本次顺带规避了这个第二层问题）。

**验证方式（可复用）**

1. **CDP 探测**（Edge headless + `Runtime.evaluate` 读真实计算样式）：`getComputedStyle(btn)`
   应为 `background-color: rgb(29,122,224)`、`border-radius: 8px`；修复前是 `rgba(0,0,0,0)` / `0px`。
2. **Layer 阶梯探针**：注入 5 个 layer 各写一种颜色，赢家必须是 `utilities`（黄）；
   修复前赢家是 `components`（绿）。
3. **`--tw-shadow` 非空**（证明 `properties` 仍在最低层）。
4. **冷启动复核**：`rm -rf packages/react/examples/basic/node_modules/.vite` + 重启 dev server，重跑 1–3。
5. `pnpm typecheck` 0 错误；`pnpm --filter @chahu/cha-set test` 100 文件 / 552 测试全绿。
6. 截图对比：`.visual-diff/cascade-layer-{before,after}.png`（`*.png` 已 gitignore）。

**经验**：`@layer` 顺序声明必须出现在**该文件首个使用该 layer 的块之前**；
库有多个 CSS 入口、各自被单独注入时，只有每个入口都声明完整顺序，结果才与注入顺序无关。

**Git 事故（同一环境坑，本项目第 3 次踩）**

- 在默认（沙箱内）执行 `git rebase`：被 SIGTERM 打断后，`.git/refs/` **整个目录**与
  `.git/objects/pack/*.pack` **同时消失**，git 报 `fatal: not a git repository` / `bad object HEAD`。
- **恢复手法（本次新增步骤，值得记）**
  1. 先 `cp -r .git <仓库外备份>`；
  2. 删掉坏 ref：`rm -f .git/refs/heads/main`；
  3. `git fetch origin '+refs/heads/*:refs/remotes/origin/*' --force` 拉回全部对象
     （**必须在 `dangerouslyDisableSandbox: true` 下**，沙箱内 fetch 报成功但对象不落盘）；
  4. `git update-ref refs/heads/main refs/remotes/origin/main` 重建本地分支；
  5. **索引修复（新学到）**：旧 `.git/index` 引用了已丢失的 blob，`git reset --mixed HEAD` 会直接失败
     （`fatal: unable to read <sha>`）→ 改用 **`git read-tree HEAD`** 用 HEAD 的树重建索引，
     再 `git checkout -- <file>` 把工作区对齐（本次据此把他人 `fix(tabs)` 的
     `qt/src/ChaSetTabsList.qml` 恢复为远端版本，未丢他人改动）。
- 教训重申（见本文件前文「环境（重要）」）：**git 读写一律 `dangerouslyDisableSandbox: true`**；
  本机 `refs/remotes/*` 始终写不进去，push 用显式 refspec `git push origin main:main`
  （本地为远端后代时是 fast-forward，无需 lease）。仓库状态干净，仅剩既有未跟踪目录 `build/`。
- 本次提交：`3e717fe fix(react): pin cascade-layer order before motion utilities block`
  （已推送，远端 main = 3e717fe）。
